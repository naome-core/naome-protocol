# Archive manifests and laboratory custody

## Scope and migration

Each laboratory owns an independently writable custody shard. All active consumers use one manifest. A scientific receipt stores its compact canonical bytes as evidence. Search and disclosure name the same head. A pinned manifest establishes membership when its inventory witnesses are available. Complete declared-edge coverage additionally requires verified custody admission.

The active manifest serializes compact UTF-8 JSON fields in order `source`, `parents`, `inventory`, `count`, `custody`. The source contains 1–256 UTF-8 bytes. Parents are up to 64 sorted distinct protocol IDs. Inventory and custody are content IDs. Count is a nonnegative integer. The head ID uses the ordinary blob preimage over these bytes. Record formats A and B, payload hashes and versioned scientific rules retain their independent identities.

`migrate-archive SOURCE DESTINATION` obtains a consistent SQLite copy with a read-only source connection, converts it transactionally and publishes the copy at a new path. Writable opens upgrade an earlier project catalog. For each flat head the converter checks its original bytes and ID, seals the same membership, preserves exact historical evidence and records the new ID. The original manifest remains separately addressable for frozen receipt rules. Declared historical parent pins stay meaningful through this mapping. Published and suspended releases, import status, selected search views, access policies and withdrawal markers are preserved. A missing member remains explicit and keeps routing coverage open. Earlier draft laboratory forks are replayed from their verified member bytes, with original descriptor and routing receipt IDs retained. An unrepresentable source label, parent count or invalid stored input produces a conversion error. Copy migration leaves its source and any existing destination intact.

`migrated-head OLD_ID` looks up the active head. Membership conversion preserves logical objects and epistemic history. Consumers comparing packet or head bytes must use the archived source version or its stored historical evidence. Current exports always write the active format.

## Immutable pages and heads

The existing blob hash is the identifier of the exact compact UTF-8 JSON encoding of a page, descriptor or federation. Canonical string escaping is the compact JSON convention specified in the whitepaper. A page is an externally tagged JSON object with one member, `Leaf` or `Branch`. Its value is a list of up to 32 ordered pairs of ASCII key and protocol ID. Only an empty root leaf can have zero pairs. A leaf stores a value. A branch stores the lowest key and child page ID. A page is at most 16 KiB. Tree order is ascending byte order. Page identity is independent of SQLite row numbers and local segment offsets.

The reference store may retain a physical splice against a prior page with the same logical ID convention. A splice stores a base digest, byte counts of an unchanged prefix and suffix, and replacement bytes. It is chosen only when it saves space. A full page is mandatory after four splice levels. Reading verifies the reconstructed bytes at each level. Existing full pages and logical identifier derivation are compatible. A logical page read therefore costs at most five backing-row reads. The implementation measures both.

A batch sorts its key edits and descends only into affected children. A duplicate key must have the same value. Partition an overflowing vector into ceil(length / 32) contiguous groups, taking ceil(remaining entries / remaining groups) at each step. Apply the same rule upwards until there is one root. Persist new pages alongside old pages. Identical content is shared. Different batching or ancestry can produce different roots for the same final set.

The custody descriptor serializes `origins`, `inventory`, `count`, `bootstrap`, `source`, `parent`, `ancestors`, `sequence`, `tree`, `delta`, `missing`, `unresolved`, `opaque`, `restricted` in that order. Its blob ID is the manifest's custody commitment. Origins are the declared manifest parents. The optional physical parent is the previous batch on this lineage. Ancestor i is the head reached after 2^i physical parent steps. Sequence starts at one. Each delta member serializes `id`, `access`, `position` and, only when true, `absent`. An absent parent or position is null. Positions contain `stream` and unsigned `block`. An absent member is a membership declaration without readable bytes. Genesis with bootstrap derives the public, read-only and two profile blobs. A selected scientific cut admits exactly its declared set, including an empty set.

The membership tree stores the canonical ID string as key and that same ID as value. The custody tree additionally indexes access descriptors, edges and positions. Both roots are derived during admission. Scientific discovery and evaluation can materialize a complete membership view. Direct CLI resolution and ordinary read-stream interchange traverse authenticated pages. Sealing a full cut with a compatible full parent reads new deposit rows using an indexed serial watermark. A withdrawal changes the epoch and forces the next full cut to rebuild membership. A first or unrelated full cut visits all available members in bounded batches. Size and complexity of matching evidence, full scientific scans and selected dependency closures can grow with the request.

Admission verifies each member's bytes and envelope access. It indexes up to 4,096 declared envelope edges per batch. A record exceeding the remaining edge budget stays readable and marks the coverage opaque. The member and byte limits are specified below. It derives the following entries within the same transaction.

| Key | Bound value |
| --- | --- |
| `o/id` | Member access descriptor |
| `d/id` | Required ID, including access and profile dependencies |
| `f/dependent/premise` | Declared premise, including envelope and raw-stream dependencies |
| `r/premise/dependent` | Declared dependent |
| `c/premise/notice` | Notice with an explicit link to the premise |
| `b/stream/ordinal` | Raw block ID at a 16-digit lowercase hexadecimal index |

Record definitions use canonical envelopes. Opaque records and mappings requiring semantic equivalence increment the unresolved-semantics count. A notice without a recognized target, calibration or source-version link also increments it. The missing count is the exact cardinality of required IDs absent from this tip. Remember up to 64 unresolved IDs for potential resolution across shards. When a previously absent member arrives, decrement the count once. A source containing a member outside the built-in public/read-only policies is marked restricted for whole-head disclosure and coverage claims. The local resolver checks the actual policy for each read.

Segmented small records keep an indexed (segment, offset, length) location. A segment contains at most one batch of canonical record bytes. Raw blocks are individually verified blobs of at most 256 KiB. A fixed-head range read checks the stream descriptor, each occupied ordinal, each block's access and exact bytes. Short blocks do not imply zero padding. The command accepts at most 4 MiB per range. Stream capture reads incrementally, deposits bounded batches and returns the final head, length, block count and SHA-256 of the bytes it read. The descriptor ID supplied by the caller must be readable at the parent. An arbitrary sparse block map only attests its occupied positions.

## Forks, transfer and access

An independent writer owns its shard. Two writers starting from one parent can also create independent children in a shard. The private indexed tip catalog retains both children, and the old parent remains addressable. A federation serializes the sorted, unique set `heads`. It commits to a vector of immutable source cuts. Each source is acquired under its own read transaction. The caller supplies an independently trusted head pin and its custody locator. The file path is local. The source string alone does not authenticate a lab identity.

A tip grant permits retrieval of the tip and its ancestral deltas. Each export step checks the grant, source custody and withdrawal markers in its read transaction. A withdrawal blocks further grants and frames that depend on that local custody. The partial withdrawal index is queried under a fixed transfer budget (1,024 markers). Exhaustion fails closed. Retracting a grant stops subsequent exports. Independent copies already delivered have their own custody, retention and authorization decisions. No discovery, identity enrollment or remote erasure service is part of this format.

A portable frame starts with the four bytes `NAOF`. Subsequent fields have an unsigned 32-bit big-endian byte length. First comes the proposed delta head. If it differs from the pinned target, follow it with head descriptors starting at the target. At each proof step, take the largest power-of-two jump that does not pass the proposed sequence. The verifier recomputes each ID and requires the committed next ID, source continuity and correct sequence distance. There are at most 64 proof descriptors, each at most 32 KiB. Then follow exactly the delta's members, in order, with raw length-prefixed bytes. Extra bytes or an incomplete field invalidate the frame. The receiver requires the admitted parent and rederives pages, coverage counters, ancestry and head ID. It commits the head, private tip, members, packs, pages and indexes together. A prefix admission never asserts availability of the final target. A duplicate frame preserves its original head.

The local pull command uses this frame encoder and decoder. It uses indexed ancestry and a binary search to locate an already admitted prefix, accepts at most the requested number of batches, and reports the confirmed cursor. The sender and receiver can instead exchange individual frame files with `export-step` and `import-step`. A sender can service several destinations independently. A slow receiver keeps a durable cursor. The qualification workload uses two bounded metadata slots and one in-flight batch per receiving worker. Transport and production scheduling are deployment choices.

## Coverage and historical interpretation

A computed hash can authenticate a page. Completeness for declared dependencies comes from induction over admitted history. Genesis derives entries from every verified member and implicit bootstrap. A child extends a verified parent, derives every required member, edge and notice key from each new input, and updates the missing and opaque counts. The receiver performs the same operations and requires exactly the committed result. No externally supplied free-standing index can authorize a negative result.

Reverse routing discovers transitive dependents. Correction routing walks a target's declared premises and queries their notice buckets. A complete empty result is labeled `outside` for this specific structural query, across these pinned sources. Candidates give `review`; they still need authorization, scope intersection and scientific adjudication under the relevant evaluator. A missing source, unreadable page, unrecognized semantics, restricted view, unresolved premise, relevant withdrawal or exhausted work budget gives `open`. Negative claims about undeclared real-world relationships are outside the protocol's evidence. Unrelated withdrawals can exhaust the bounded search and produce a conservative open answer. A bounded cross-shard lookup may close a locally missing premise when every missing ID is accounted for and visible at another pinned source.

A compact routing receipt binds the evaluator, mode, target, budget, sorted head pins, view ID, result count, result-set digest, standing and failure reason. It is private local metadata. It remains readable by ID after later custody changes. A repeated query may now be open. Historical scientific receipts replay using their original manifest bytes and evaluator IDs. Current scientific evaluators consume the active manifest. Structural routing supplies candidates and coverage for its declared-edge rule.

## Work and storage bounds

Let H be the tree height, S the number of commits on a selected lineage, k the number of derived keys in a bounded delta, L the number of pinned heads and B a query work budget.

- An exact key lookup reads at most H logical pages. A single insertion reads at most H and creates at most 2H+1 pages. A k-key edit can touch O(kH) pages including splits. Admission also makes O(k) exact coverage lookups. Each logical page has a 16 KiB maximum. Head and jump metadata add O(log S) identifiers per commit. SQLite index, journaling and filesystem I/O are additional costs.
- A range touching t blocks uses O((t+1)H) logical page reads and fetches at most t blocks plus the bounded stream descriptor. A record location resolves via a primary key and a bounded segment. The maximum range output and admitted bytes bound buffer memory independently of prior inventory size.
- Prefix routing visits boundary paths and matching leaves. Width, traversal budget and the number of sources bound work. A conservative upper bound is O((LB+B+L)H) page reads including live withdrawal checks, with O(B+64L) retained IDs plus bounded pages and descriptors. A query approaching the entire dependency graph pays for its matches or returns open at its budget.
- Finding a local resume cursor takes O(log² S) indexed ancestry probes. An exported step carries one bounded batch plus O(log S) bounded ancestry descriptors. The immediately next target needs no intermediate proof. A fully admitted local target transfers zero member or frame bytes. Each receiving worker needs one bounded frame, one decoded batch, one pack, bounded edits and root-to-leaf scratch space. A portable writer streams individual fields.
- Cold admission must verify every new member and derive its index. For independent batches with k_i derived keys the retained page work is O(sum k_i H_i), plus payload bytes and ancestry metadata. Immutable snapshots retain old paths. No constant storage-amplification bound relative to raw scientific payload size is asserted. Small records with a long retained history can incur substantial overhead. A cold pull replays the selected ancestry, including the portable proof for each step.
- Each physical shard has one local SQLite writer. Independent shards avoid a shared payload transaction. Coordination costs grow with pinned tips; the implemented view limit is 64. A reverse membership index suspends bounded published releases affected by withdrawal. Disk capacity, backup, compaction, remote authorization and high-load service capacity need deployment-specific qualification.

The [qualification method](qualification.md) and [results](results.md) describe the workload and link to the original measurements. The repository and Cargo source package include the reproduction driver.

## Interchange and resource limits

The self-contained JSON exchange carries a compact manifest, membership witnesses and permitted packets. Omitted members are derived from authenticated membership minus the received packet IDs. Linked scientific horizon blobs can carry additional inventory witnesses. The offline read stream sends the compact header, bounded page rows, ordered packet rows and a null terminator. Its sender traverses the membership tree; its receiver verifies pages and packet membership in a single transaction. JSON bundles and scientific training disclosure can materialize membership. A bounded whole-release message serializes its manifest and page witnesses together. A portable custody frame instead re-derives its coverage and membership trees from its parent and delta. An independently named historical horizon needs its own inventory witnesses at the receiver for scientific replay. A missing witness cannot authorize a positive historical judgment.

An ordinary batch admits up to 64 submitted members and 4 MiB of inputs. One intact logical object can use the record-format limit of 16 MiB, plus genesis descriptors when applicable. A large single blob is retained in 256 KiB extents, resolved under its original logical ID, and checked after assembly. Deliberate raw-stream capture keeps block-addressed access. Individual logical blob resolution may allocate its full 16 MiB. These bounds apply to admission, distinct from the tighter limits of the bounded complete-release API.
